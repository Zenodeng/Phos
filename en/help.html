Four steps to start editing.

Phos isn’t notarized by Apple yet, so macOS asks for permission once on first launch and never again. This is how macOS treats every non-notarized app — not something unique to Phos.

Download and open the disk image

Click “Download for macOS” on this page, or use this direct link, download Phos-macOS-apple-silicon.dmg, then double-click to open.

Drag it into Applications

In the disk image window, drag Phos into the Applications folder next to it, then eject the image.

Allow it on first launch

Phos is locally signed but not notarized by Apple, so it is blocked the first time. Double-click Phos, click “Done” to dismiss the dialog, then immediately open System Settings → Privacy & Security, scroll to the bottom, and click “Open Anyway”.

That button disappears about an hour after the dialog appears, so click it right away. After that, double-clicking opens the app normally.

Or skip it with one command

Run this line in Terminal to remove the quarantine flag; after that a double-click opens it:

xattr -dr com.apple.quarantine /Applications/Phos.app

Complete Guide to Connecting & Deploying Local AI Models

Phos uses a three-tier on-device AI architecture — all inference runs locally on your Mac and photos never leave your machine. Tier 1 works immediately after installing Phos; Tiers 2 and 3 are strictly optional drop-in upgrades that activate automatically once installed.

Tier 1 · Built-in

Zero-Download Native AI

Pure Swift, Metal & Apple Vision. Includes Native AI Edit, Reference Color Match, Subject / Person / 8-part Portrait masks, 4-level PatchMatch Remove, zero-model Sky & Depth, YCoCg RAW Denoise, 2x Sharpened Super Res, Smart Culling and bilingual search.

Tier 2 · Zero Python

5-Slot Core ML Neural Models

Native Apple Neural Engine & GPU models stored under ~/Library/Application Support/Phos/Models/ (~337 MB total for all 5 slots). Any uninstalled slot seamlessly falls back to Tier 1.

Tier 3 · Optional VLM

Qwen3-VL-4B / MLX Local Server

Open-ended natural-language prompting. Stored under ~/Library/Application Support/Phos/MLX/ (~3.1 GB base weights + bundled 1.3 MB LoRA adapter). Phos spawns an offline 127.0.0.1 local server on demand.

2. Three Ways to Deploy & Connect Core ML Models

Method A · One-Command Shell Scripts (Recommended)

Each script downloads the pinned weights from Hugging Face, verifies every file’s SHA-256 checksum, compiles via xcrun coremlcompiler, and atomically installs into ~/Library/Application Support/Phos/Models/.

Requires Xcode or Xcode Command Line Tools (xcrun coremlcompiler).

Method B · In-App GUI Import (No Terminal)

  1. Download any .mlpackage from the table above (unzip if .zip; ignore any __MACOSX folder).
  2. Open Phos → click “AI Edit” at the top of the right inspector → switch to the “Model Hub” tab.
  3. Click “Import…” on the matching slot and pick the .mlpackage or .mlmodelc bundle. Phos compiles and activates it immediately without restarting.
# 1) Install all 5 Core ML models at once (~337 MB total)
git clone https://github.com/Zenodeng/Phos.git && cd Phos
bash Scripts/install_all_coreml_models.sh

# 2) Or install individual slots on demand (LaMa supports --512 or --1024)
bash Scripts/install_lama_model.sh --512
bash Scripts/install_sky_model.sh
bash Scripts/install_depth_model.sh
bash Scripts/install_denoise_model.sh
bash Scripts/install_superres_model.sh

# 3) Mainland China mirror (uses hf-mirror.com with identical SHA-256 checks)
HF_ENDPOINT=https://hf-mirror.com bash Scripts/install_all_coreml_models.sh

Method C · Manual Compile or Custom Models: Phos supports both Image and MLMultiArray (NCHW/NHWC, FP16/FP32) Core ML models and reads tile dimensions directly from the model metadata. Compile manually or import via Model Hub:

mkdir -p "$HOME/Library/Application Support/Phos/Models"
xcrun coremlcompiler compile MyCustomModel.mlpackage "$HOME/Library/Application Support/Phos/Models"
# Rename to the exact slot filename (e.g. SuperRes.mlmodelc) and open AI Edit → Model Hub

3. Optional Advanced Mode: Local Multimodal VLM (Qwen3-VL-4B / MLX)

  • Phos-Optional-Model-Installer.zip6.7 KB · installer scripts & SHA-256 manifest only

If you want free-form natural-language prompting powered by a local 4B vision-language model, install the ~3.1 GB Qwen3-VL-4B-Instruct-4bit base model and MLX runtime (Phos already bundles the ~1.3 MB fine-tuned LoRA adapter and attaches it automatically). Completely optional — skipping it never affects standard editing or any of the 5 Core ML slots above.

Requirements: Apple-silicon Mac (macOS 26+) · arm64 Python 3.11 (python.org universal2 installer) · at least 8 GB free disk space · 16 GB+ unified memory recommended.

  1. Install Python 3.11 and verify python3.11 --version prints a version in Terminal.
  2. Run the installer. Unzip Phos-Optional-Model-Installer.zip, right-click “安装模型.command” → “Open” (or “国内网络安装.command” in mainland China to use hf-mirror.com and the Tsinghua PyPI mirror while still checking all 16 SHA-256 hashes).
  3. Connect inside Phos. It installs to ~/Library/Application Support/Phos/MLX by default. Open any photo → click “AI Edit” → bottom-left “Open Legacy MLX-VLM Window…”. On your first prompt, Phos automatically launches an offline local server (HF_HUB_OFFLINE=1) on http://127.0.0.1:8765 (auto-selecting a free port if occupied), mounts the bundled LoRA adapter, and terminates cleanly when Phos quits.
# Manual install using China mirrors
HF_ENDPOINT=https://hf-mirror.com PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple python3.11 install_model.py

# Verify an existing MLX environment and all 16 model checksums
python3 install_model.py --verify-only

# Install to a custom path (then pick the outer folder containing .venv and model inside Phos)
python3.11 install_model.py --environment /absolute/path/Phos-MLX

Model Deployment FAQ

Do I need to restart Phos after installing Core ML models?

No. Importing via Model Hub hot-reloads immediately; after installing via terminal scripts into ~/Library/Application Support/Phos/Models/, opening Model Hub refreshes status and the Remove brush, Sky mask, Optical Bokeh, AI Denoise, and 2x Super Res export automatically pick up the installed weights.

What if xcrun coremlcompiler is not found?

Run xcode-select --install (or install Xcode) before running the shell scripts. Alternatively, download any .mlpackage manually and import it inside Phos “AI Edit → Model Hub” — macOS compiles it automatically via MLModel.compileModel.

It says “Please install Apple Silicon Python 3.11”

Only Tier 3 (Qwen3-VL MLX) requires Python 3.11 — Tier 1 Native AI and all 5 Tier 2 Core ML models are 100% Python-free. Reinstall the macOS universal2 Python 3.11 package from python.org if you want Qwen3-VL.

How do I troubleshoot the local MLX server?

Run python3 install_model.py --verify-only to verify weights and imports, then inspect ~/Library/Logs/Phos-MLX.log. Never move an existing .venv folder (it stores absolute paths); use --environment to install into a new path instead.

Do any models upload my photos?

Never. All 5 Core ML models run in-process on Apple Neural Engine / Metal, and the optional Qwen3-VL MLX server binds strictly to loopback 127.0.0.1 with HF_HUB_OFFLINE=1. Internet access is used only while downloading weights.

All third-party upstream models retain their original open-source licenses: solume-big-lama-coreml (Apache-2.0), melmass/skyseg-coreml (MIT), apple/coreml-depth-anything-v2-small (Apache-2.0), markhamilton/scunet-coreml (Apache-2.0), marshiyar/RealESRGAN_x2_CoreML (MIT), and mlx-community/Qwen3-VL-4B-Instruct-4bit (Apache-2.0).

Optional: curated film LUT pack (34 sRGB-ready looks)

  • Phos-Optional-LUT-Installer.zip13.8 KB · installer script & license manifest (8ebdcc39…eb71)

Phos keeps the app bundle lightweight and does not bundle hundreds of megabytes of third-party LUT files. This standalone 13.8 KB package contains no bundled LUT binaries — using macOS’s built-in Python 3 standard library, it fetches 34 de-duplicated, sRGB / Rec.709-ready presets directly from upstream authors (~30–40 MB via HTTP range requests) into ~/Documents/RawTherapee/HaldCLUT.

Includes 18 RawTherapee classics & Polaroid looks (Portra, Ektar, Kodachrome, 400H, HP5, Polaroid), 5 Stuart Sowerby Fuji X-Trans III presets, 3 abpy X-Trans IV Provia → sRGB profiles, 2 PictureFX looks, 4 IWLTBAP Freeware grades, plus locally baked sRGB → Linear → Cineon Log adaptations of Kodak 2383 D65 and Fujifilm 3513DI D65 so shadows never crush on sRGB images.

To install: unzip and double-click 安装精选胶片LUT.command (or run python3 install_luts.py). Existing directories can be backed up first (keeping 我的LUT) or merged non-destructively. Afterwards, click Refresh under Color → Film CLUT in Phos. Third-party license notices are inside LICENSE-THIRD-PARTY.md (abpy is CC BY-NC-SA 4.0 non-commercial; pass --skip-iwltbap to omit IWLTBAP).

Windows build · Experimental port

  • Phos-4.4.0-Windows-x64.zip407 MB · Windows 10/11 x64

Ported from the macOS 4.4.0 source, maintained separately from the macOS build, with its own version numbering. The ZIP contains a Phos-4.4.0-Windows-x64 folder — unzip it, open that folder and double-click Phos.exe; it must stay alongside the app\ folder. Requires 64-bit Windows 10/11 and a D3D11-capable GPU. You can verify the download first with SHA256-Windows.txt (Get-FileHash).

It isn’t exactly the same as the macOS build. Apple’s Vision and Core Image are replaced with local implementations (MODNet / BiRefNet / OpenCV / D3D11), so subject segmentation, edges, and color can differ. The 4.4 features are in this build: lens correction (5 bundled profiles, external XML import, before/after comparison and an 8-way grid), the bilingual interface, and background LUT scanning.

On-device AI editing works, but the base model is not bundled. Follow the in-app prompt to download the Qwen3-VL-4B base model (~3.1 GB) and the P2 weights (~1.3 MB), then click “prepare and use”. Preparation runs offline and needs about 16 GB of free disk. The portrait / foreground segmentation and CLIP models ship with the package, so ordinary editing works without any download.

It isn’t code-signed, so the first launch is blocked by Windows SmartScreen — click “More info → Run anyway”. Full differences and known limitations are in the release notes.
